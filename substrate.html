What it installs

substrateRedis. The shared state: folds, node heartbeats, field events. Loopback only, no host mapping.
rune_engineGo binary. Semantic router: 34 strata, 309 keywords, 1,760 automaton nodes, one pass per query. ~200 ns/scan.
core_nodeNode 0. Routes a fold to the rings that own it, enforces quorum, records the result.
ring_1 … ring_12Twelve persona nodes. Each with a role, a domain and an axiom preset. Ring 6 is the Warden — strictest gate.
persona_routerThe front end. One base model, twelve masks. Injects the persona, enforces the gate, answers system facts from the index.
gatewayOptional. The only public process: bearer auth, per-key rate limit, nonce replay guard, forwards to the private core.

The Harness on the free page is the front end alone, in one executable. This installer adds the substrate and the twelve rings as real services — the part that survives a reboot, a second user, and a restart.

Why it is the breakthrough

The free harness proves the loop on one machine. The installer makes it a system: state that persists, nodes that are addressed rather than simulated, a router that can be reached by anything on the network, and a gateway that decides access without exposing what is behind it.

  • Facts are answered by the index at 7–11 ms, deterministic, no model involved.
  • A fold is routed by domain, not broadcast blindly — and a node answering outside its domain is rejected by axiom 6.
  • Quorum counts only axiom-valid results. Mis-routing is visible, not silent.
  • Every hop is signed (HMAC), replay-protected (per-node nonce), and visible in the field store.
  • Manifest-verified backup: images, volumes, container specs, networks, configs, SHA-256 per file.

Install order

Each step waits for health before the next. On a clean machine this is one command per line, in this order:

docker compose -f docker-compose.mesh.yml up -d redis
docker exec mesh-redis redis-cli ping                 # PONG

docker compose -f docker-compose.mesh.yml up -d rune-engine
curl -s http://127.0.0.1:9400/health                   # {"ok":true,...}

docker compose -f docker-compose.mesh.yml up -d core
curl -s http://127.0.0.1:9410/health                   # {"ok":true,"rings":12}

docker compose -f docker-compose.mesh.yml up -d ring-01 ... ring-12
docker compose -f docker-compose.mesh.yml up -d entropy energy

ollama pull claude-7:50duo50quin5                       # 2.8 GB face tier
python persona_router.py                                # 127.0.0.1:8421

./OroborosHiveHarness.exe                              # the front end

All four health checks returning 200 means the stack is live end to end. The gateway is only required for the managed placement.

Requirements

  • Docker Desktop (Windows) or Docker Engine (Linux)
  • 16 GB RAM recommended — twelve rings plus a model
  • ~25 GB free disk for images, volumes and the model tier
  • Ollama for local prose; the index and the mesh run without it

What it does not do

  • No training on your prompts.
  • No factual verification beyond the index layer — the gate checks structure, not truth.
  • No hidden access: the gateway is the only public process, and it returns answers, not topology.
  • No guarantee of correctness on open reasoning. That limit is the same at every tier and it is stated on the free page too.
